## (개인·필수) 문제 1 — 사용자와 판단 하나로 좁히기

Dashboard를 사용할 사람 한 명과 그 사람이 내릴 판단 하나를 정하세요.

### 답안

- 내 주제: Beauty Finder — 사용자 조건 기반 화장품 검색·분석
- 한 문서의 의미: 화장품 상품 1건
- 사용자 한 명: 자신의 퍼스널컬러가 겨쿨인 20대 소비자
- 사용자가 반복해서 하는 일: 새 화장품을 살 때 내 퍼스널컬러·예산에 맞는 상품을 찾음
- Dashboard를 보고 결정할 것: 어떤 카테고리·브랜드를 우선 살펴볼지
- 결정 뒤 수행할 행동: 해당 카테고리·브랜드로 검색을 좁혀 구매 후보를 고름
- 사용자에게 필요 없는 정보: 재고 관리용 수치, 물류·창고 정보

`모든 사용자`, `전체 현황`, `데이터를 본다`처럼 넓은 표현은 한 사람과 한 행동으로 좁힙니다.

## (개인·필수) 문제 2 — 서로 중복되지 않는 질문 4개

다음 역할을 하나씩 사용해 질문 4개를 작성하세요.

1. 전체 규모
2. 그룹 비교
3. 수치 분포 또는 정확한 값 비교
4. 상태 비율 또는 시간 변화

| 번호 | 분석 질문 | 질문의 답으로 내릴 판단 | 다른 질문과 겹치지 않는 이유 |
|---|---|---|---|
| Q1 | 검색 대상 상품은 모두 몇 개인가 | 데이터 규모·신뢰도 판단 | 전체 1개 값만 보는 규모 질문 |
| Q2 | 카테고리별 상품 수는 어떻게 다른가 | 어떤 카테고리부터 볼지 | 그룹(category) 간 비교 |
| Q3 | 브랜드별 상품 수·평균 가격·평균 평점은 | 예산·평점 기준 브랜드 선택 | 브랜드별 정확한 수치 비교(표) |
| Q4 | 퍼스널컬러별 상품 구성 비율은 | 내 컬러에 맞는 상품이 충분한지 | 상태(personal_color) 구성 비율 |

## (개인·필수) 문제 3 — 질문별 field 존재 여부 점검

각 질문에 필요한 field가 실제 mapping과 문서에 있는지 확인하세요.

| 질문 | 필요한 field | mapping type | 실제 존재 | 값이 충분히 분포 | 가능/가공 필요/추가 필요 |
|---|---|---|---|---|---|
| Q1 | (Records) | - | 예 | 1,000건 | 가능 |
| Q2 | category | keyword | 예 | 6종 140~187 | 가능 |
| Q3 | brand, price, rating | keyword, integer, float | 예 | brand 20+종, price 8,100~64,500, rating 2~5 | 가능 |
| Q4 | personal_color | keyword | 예 | 4종 236~263 | 가능 |

- 현재 데이터로 바로 만들 수 있는 질문 수: 4
- 선택한 A/B/C 경로: A (개인 데이터로 제작)
- 선택 이유: Q1~Q4에 필요한 field가 모두 beauty-products에 존재하고 값도 충분히 분포함

## (개인·필수) 문제 4 — 부족한 데이터 생성 규칙 설계

현재 답할 수 없는 질문 하나를 선택하고 필요한 데이터를 구체화하세요.

- 답할 수 없는 질문: "어떤 상품이 실제로 많이 팔렸는가"
- 부족한 field: sales_count(판매량)
- mapping type: integer
- 예시값 3개: 12000, 3500, 250
- 범주라면 고유값 수: 해당 없음(수치)
- 수치라면 최소·최대·대표 구간: 0 ~ 50,000, 대표 구간 100~5,000(대부분), 상위 5%는 10,000 이상
- 상태라면 예상 비율: 해당 없음
- 날짜라면 기간과 단위: 판매 시점을 sold_at으로 추가 시 2023-01~2026-07, 월 단위
- 다른 field와 필요한 관계: rating이 높고 review_count가 많은 상품일수록 sales_count가 크게(양의 상관) 생성
- 한 문서를 생성하는 규칙: 상품별 base = review_count × (rating/5) × 브랜드 인지도 계수 + 노이즈
- 필요한 문서 수와 이유: 기존 1,000 상품에 field만 추가(문서 수 유지) — 비교·분포·필터가 이미 성립
- seed 고정 여부: 고정(재현성 확보)
- 생성 후 검증 방법: sales_count 분포가 소수 상품에 편중(로그 분포)되는지, 상위 판매 상품이 고평점 상품과 겹치는지 aggregation으로 확인

"랜덤으로 많이 만든다"는 규칙이 아닙니다. Dashboard에서 비교·분포·필터 결과가 나타나도록 값의 범위와 관계를 적습니다.
