## (공통·필수) 문제 1 — 50,000원 단위 가격 분포

`price`와 Count of records를 사용해 가격대별 Bar를 만드세요. 자동 막대 수를 맞추려고 `Decrease granularity`를 반복하지 말고 `Create custom ranges`를 사용합니다.

권장 구간 예:

- 0 이상 50,000 미만
- 50,000 이상 100,000 미만
- 100,000 이상 150,000 미만
- 150,000 이상 200,000 미만
- 200,000 이상

### 결과 입력

- 실제 입력한 구간: 0–50,000 / 50,000–100,000 / 100,000–150,000 / 150,000–200,000 / 200,000 이상
- 구간 사이 빈틈·중복 확인 방법: 각 구간의 "이상~미만"으로 경계 하나씩만 포함되게 설정하고, 다섯 구간 문서 수 합(7,220+4,685+2,663+2,561+2,871=20,000)이 전체와 같은지로 확인
- 가장 많은 가격 구간: 0–50,000
- 해당 구간 실제 문서 수: 7,220
- 제목: 가격 구간별 상품 수
- 캡처 파일: `../captures/c-p04-distribution.png`

## (공통·필수) 문제 2 — 재고 상태 Donut과 기준값 검증

차트 유형 `Pie`에서 `in_stock` Top values와 Count of records를 설정한 뒤, `Style → Appearance → Donut hole → Medium`으로 Donut을 만드세요. 차트 목록에서 Donut을 찾지 않습니다.

### 결과 입력

- true 실제 값: 16,998
- false 실제 값: 3,002
- 합계: 20,000
- 전체 20,000과 일치하는가: 예
- 비율 또는 값 표시 방식: 값과 백분율 함께 표시 (true 약 85.0%, false 약 15.0%)
- 제목: 재고 상태 비율
- 한 조각만 보일 때 먼저 확인할 조건: KQL/filter에 `in_stock` 조건이 걸려 한쪽만 남았는지, 그리고 Top values 개수가 1로 줄었는지 확인
- 캡처 파일: `../captures/c-p04-distribution.png`

## (공통·필수) 문제 3 — 월별 상품 등록 Line과 잘못된 해석 수정

`created_at` Date histogram과 Count of records를 사용하고 `Minimum interval`에 `1M`을 입력해 월 단위 Line을 만드세요.

다음 문장을 데이터에 맞게 수정하세요.

> 월별 판매량이 증가하거나 감소하는 모습을 보여 준다.

### 결과 입력

- 선택한 interval: 1M (월)
- 보이는 월 구간: 2025-08 ~ 2026-08 (약 13개월)
- 실제 패널 제목: 월별 상품 등록 분포
- 수정한 설명 문장: "월별로 새로 등록(created_at)된 상품 수를 보여 준다. 2025-09~2026-07은 월 1,550~1,750건으로 고르며, 첫 달(2025-08, 257)과 마지막 달(2026-08, 1,422)은 구간이 잘려 적게 보인다."
- `created_at`의 실제 의미: 상품이 색인/등록된 시점이지 판매 시점이 아님
- 판매 추이를 알려면 추가로 필요한 사건/field: 구매 이벤트를 뜻하는 `sold_at` 같은 날짜 field와 판매량 field
- 캡처 파일: `../captures/c-p04-distribution.png`

## (개인·필수) 문제 4 — 분포·비율·시간 중 하나 선택

자기 질문에 필요한 유형 하나만 선택해 설계하거나 만드세요.

| 선택 | 필요한 데이터 | 적합한 질문 예 |
|---|---|---|
| 분포 | 숫자 field | 값이 어느 구간에 몰려 있는가? |
| 비율 | 상태·범주 field | 상태별 구성은 어떠한가? |
| 시간 | 날짜 field | 기간별 문서 수는 어떻게 달라지는가? |

- 선택 유형: 비율
- 사용자 질문: 상품이 퍼스널컬러별로 어떻게 구성돼 있는가
- field와 mapping type: personal_color / keyword
- 그룹/구간/시간 단위: Top values(4), Count of records
- 차트: Donut
- 완료 기준: 4개 조각 합이 1,000이고 aggregation과 일치
- 실제 결과 또는 부족한 데이터: 겨쿨 263(26.3%), 갈웜 259(25.9%), 여쿨 242(24.2%), 봄웜 236(23.6%)
- 해석 시 주의할 한계: "겨쿨 상품이 가장 많다"까지만 말할 수 있고, 어느 퍼스널컬러가 더 잘 팔리는지는 판매 데이터가 없어 알 수 없음

## (선택 도전) 문제 5 — 가격 구간 대안 비교

50,000원 구간과 자신이 설계한 다른 구간을 비교하세요. field와 Count는 유지합니다.

| 비교 | 50,000원 단위 | 대안 구간(개인 20,000원 단위) |
|---|---|---|
| 막대 수 | 5 | 5 |
| 읽기 쉬움 | 고가 상품까지 넓게 봄 | 화장품 실제 가격대(8,100~64,500)에 맞아 촘촘 |
| 판단에 유용함 | 공통 products(고가 포함)엔 적합 | beauty-products엔 20,000원 단위가 더 유용 |

- 최종 선택과 이유: 개인 데이터엔 20,000원 단위(0–2만 250 / 2–3만 254 / 3–4만 222 / 4–5만 160 / 5만+ 114). 화장품 가격이 5만원 이하에 몰려 있어 50,000원 단위로는 막대 하나에 다 뭉쳐 분포가 안 보이기 때문
