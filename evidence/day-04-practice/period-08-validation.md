## (개인·필수) 문제 1 — 사용자 행동 두 가지 테스트

Dashboard 사용자가 실제로 할 행동 두 가지를 실행하세요. 각 행동은 조건 적용과 결과 확인, 원상 복구를 포함합니다.

| 행동 | 시작 상태 | 적용 조건 | 변한 패널·값 | 사용자의 판단 | 복구 방법 | 복구 성공 |
|---|---|---|---|---|---|---|
| 1 | 전체 1,000 | personal_color Control = 겨쿨 | Metric 1,000→263, 카테고리 최다 블러셔187→립틴트·파운데이션50 | 겨쿨은 립틴트·파운데이션부터 본다 | Control을 Any로 | 성공(1,000) |
| 2 | 전체 1,000 | KQL `price <= 20000` | Metric 1,000→250, 저가 카테고리 확인 | 2만원 이하로 살 수 있는 상품이 250개 | 검색창 비우기 | 성공(1,000) |

- 두 행동이 서로 다른 이유: 행동1은 퍼스널컬러(상태) 필터, 행동2는 가격(수치 범위) 필터로 서로 다른 조건 축을 검증
- 사용자가 멈추거나 헷갈린 지점: Control(드롭다운)과 KQL(검색창)을 처음엔 헷갈림 → label과 검색창 위치로 구분
- 캡처 파일: `../captures/p-p08-final.png`

## (개인·필수) 문제 2 — 핵심값 3개 교차 검증

Dashboard의 핵심값 3개를 Discover, `_count`, 또는 aggregation 요청과 비교하세요. `Inspect`는 Dashboard 편집 모드에서 해당 패널의 `Panel menu`에 있습니다. 권한이나 화면 상태로 보이지 않으면 Discover 또는 제공 요청 파일로 검증합니다.

| Dashboard 패널·값 | 동일하게 맞춘 시간·조건 | 비교 방법 | 비교값 | 일치 여부 | 다르면 확인한 원인 |
|---|---|---|---:|---|---|
| 전체 상품 수 Metric 1,000 | 2023-01-01~2026-09-03, 조건 없음 | `GET beauty-products/_count` | 1,000 | 일치 | - |
| 카테고리 블러셔 187 | 동일 | terms(category) aggregation | 187 | 일치 | - |
| 퍼스널컬러 겨쿨 263 | 동일 | terms(personal_color) aggregation | 263 | 일치 | - |

- 비교에 사용한 요청 파일 또는 Discover 캡처: Dev Tools `_count`, `_search` terms aggregation
- 세 값을 신뢰할 수 있는 이유: 대시보드와 aggregation이 같은 시간 범위·무조건 상태에서 정확히 일치하고, 카테고리 6종 합·퍼스널컬러 4종 합이 모두 1,000으로 맞음

## (개인·필수) 문제 3 — 문제 하나를 실제로 수정하고 재검증

제목, field, 집계, 정렬, 구간, 시간, filter, layout 중 한 문제를 골라 수정하세요. 문제가 없다고 생각되면 사용성 문제 하나를 개선합니다.

- 발견한 문제: 시간 범위 오설정으로 상품이 1,000이 아닌 약 525건만 표시됨
- 문제 유형: 시간(time range)
- 수정 전 설정 또는 결과: 시간 범위 "2y"(2024-09~2026-09) → 표시 약 525건, 브랜드 Bar에 큰 Other 막대
- 추정 원인: release_date 최소값 2023-01-04가 범위 밖으로 잘림
- 수정한 한 가지: 시간 범위를 2023-01-01~2026-09-03으로 확장
- 수정 후 결과: 전체 1,000건 표시, 브랜드 Table 정확 값
- 같은 조건 재검증 결과: `_count` 1,000과 일치
- 개선/보류/악화 판정과 근거: 개선 — 표시 문서 수가 실제 데이터(1,000)와 일치하게 됨
- 수정 전·후 캡처: `../captures/p-p08-before.png`, `../captures/p-p08-final.png`

## (개인·필수) 문제 4 — 결과 3·한계 2·필요 데이터 1과 제출

### 결과 3개

1. 조건·핵심값·비교·판단: 전체 상태에서 카테고리 최다는 블러셔 187(전체 1,000의 18.7%). aggregation과 일치 → 블러셔·립틴트 라인을 우선 노출
2. 조건·핵심값·비교·판단: personal_color=겨쿨(263)에서 최다 카테고리는 립틴트·파운데이션(각 50)으로 전체 순위(블러셔)와 다름 → 겨쿨 소비자에겐 립틴트·파운데이션 우선 추천
3. 조건·핵심값·비교·판단: 브랜드는 롬앤 111·클리오 83로 상품 수 최다지만 평균 평점은 릴리바이레드 ★3.55·웨이크메이크 ★3.56가 더 높음 → "상품이 많은 브랜드 ≠ 평점 높은 브랜드"이므로 추천 시 둘을 함께 제시

### 현재 데이터의 한계 2개

1. 판매량·재고 field가 없어 "실제 인기 상품/베스트셀러"를 말할 수 없다
2. release_date는 출시일이라 판매 추세·시즌성 분석에는 쓸 수 없다

### 추가로 필요한 데이터 1개

- field: sales_count
- mapping type: integer
- 예시값: 12000, 3500, 250
- 값 분포·생성 규칙: rating·review_count와 양의 상관을 갖도록 생성, 소수 상품에 판매 편중(로그 분포)
- 추가되면 답할 수 있는 질문: "어떤 브랜드·카테고리 상품이 실제로 많이 팔렸는가"
